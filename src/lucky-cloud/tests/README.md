# Cloud instrument verification

Run from the repository root after `python3 src/lucky/build-lucky.py`:

```sh
node --test src/lucky-cloud/tests/contracts.test.cjs
node src/lucky-cloud/tests/render-evaluation.cjs
node src/lucky-cloud/tests/locked-drum-pcm.cjs
node src/lucky-cloud/tests/browser-check.cjs
```

The browser test uses installed `playwright`, or the module named by
`PLAYWRIGHT_MODULE`. It starts a temporary local server, uses fresh browser
contexts, blocks external requests, and closes the contexts and server.
It never submits a wish or saves a supplied song. Its MIDI file is newly
generated by the tested composition. Test receipts and screenshots go to
`tests/evidence/` and are not required build inputs.

The loader reads the actual built HTML rather than a private source document.
Contract checks pin the original engine/app extraction, reject private trailing
material, and rebuild an identical page using only the public inputs. They test
deterministic scores, independent sound rolls, named presets, all six palettes,
source-validated lane captures, malformed choices, and balanced MIDI events.

The PCM sweep uses one fresh SHA-derived seed for each of the 23 inherited
styles at both 44.1 and 48 kHz. Each render includes playback, a sound-roll
crossfade and the Stop tail. It measures finite samples, peak, RMS and DC.
Eight separate comparisons check that adjacent sound rolls change the actual
rendered voice while preserving the score. The lock test compares the actual
Part/Kit output at both rates with fixed trigger/RNG and the UI-pinned tonal
frame; it isolates locked drum gain from the surrounding new composition.

The cloud browser checks exercise real audio in Chromium and Playwright WebKit,
the original dice entrance, sound rolls while playing, pause/replay, hash/history
restore, temporary history in opaque frames, early Stop races, disposal, MIDI
export, WAV cancellation, 320/390/768/1440 layouts, keyboard dialogs and denied
clipboard fallback. Clipboard success uses a recording stub; the test does not
write to the host clipboard.

These tests do not establish musical taste, cultural authenticity, source rights,
physical Safari/iPhone performance, hardware MIDI behavior or public deployment.
Filter variables `CLOUD_EVAL_STYLES` and `CLOUD_EVAL_RATES` support diagnosis;
a filtered run is not the full release gate.
